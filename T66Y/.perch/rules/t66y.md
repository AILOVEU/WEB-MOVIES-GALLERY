# T66Y 项目规则

## 数据流

`_rawdata/fid<N>_p<NNNN>.html`（原始页，不可再生）
  → `_scripts/common/t66y.py` 解析 + 打标签
  → `_scripts/site/build.py` 组装 `data/`
  → `index.html` + `assets/app.js` 渲染

改标签规则只动 `_scripts/config/tags.json` 再跑 build，**不用重抓**。

## 硬约束

1. **游客只能翻到第 100 页**（2026-11-24 实测）。第 101 页起返回「您沒有登錄或者您沒有權限」。
   要全库 4957 页必须在 `_pipeline/cookie.txt` 放登录 cookie。crawl.py 连续撞 3 次登录墙会自动停。

2. **不抓帖子详情**。这个项目的定位是清单筛选，点标题跳回 t66y 原页面。
   不要为了「更完整」去加详情抓取 —— 那是另一个项目（参考 JAVBUS 的做法）。

3. **分片按绝对页码切**，不是按 tid 也不是按 page_min 偏移：
   `shard_of_page(pg) = (pg - 1) // 50`。前端 `shardOfPage()` 必须与 `paths.shard_of_page()` 同口径，
   两边不一致会导致加载错片、数据对不上。

4. **列表页解析的两个坑**（都踩过，别改回去）：
   - 行锚点用 `class="tr3 t_one tac"`，不能按 `<tr` 切 —— 正文 td 里可能嵌套表格。
   - 回复/下载两列**不能按位置硬取**：下载列可能是空的 `<td></td>`，
     空列会让索引滑到下一列，把 `read.php?tid=` 里的 tid 当成下载数（实测 tid=7472647）。
     正确做法是按内容判定：纯数字才算，空/`--` 记 0，遇到非数字列就停。

5. **时间一律用 `data-timestamp`**（epoch 秒），不要用页面上的「昨天 16:43」「15 小時」相对文本。
   「最後發表」的时间戳没有 `s` 后缀，作者栏的有，两种都要认。

6. **数据分三层**，不要合并成一个大文件：
   - `index.js`：元信息 + 每页标签位图（几十 KB，首屏）
   - `shard_XXX.js`：每片 50 页完整记录（约 2 MB，按需注入）
   - `titles_XXX.js`：每片标题索引（约 300 KB，搜索时才加载）
   全库 49 万条 ≈ 185 MB，一次加载浏览器扛不住。

## 代理

直连不通，必须走 `127.0.0.1:7890`（`T66Y_PROXY` 环境变量可覆盖）。
curl 必须带 `--ssl-no-revoke`，否则 Windows schannel 的吊销检查会报 CRYPT_E_REVOCATION_OFFLINE。

## 日志与备份

- 日志：`_logs/YYYY-MM-DD/`，截图 `_logs/shots/YYYY-MM-DD/`
- 备份：`_bak/YYYY-MM-DD/`，build 覆盖 data/ 前自动留，同日多次跑只留最后一次
- `_logs/` 和 `_bak/` 随便删，不丢数据；`_rawdata/` 和 `_pipeline/` 删了要重爬
